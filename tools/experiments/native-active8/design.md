## Smallest isolated change

Ordinary B1 attention has16 independent query-head jobs. Twelve equal contiguous partitions give eight workers one head and four workers two heads; eight partitions give each useful worker two heads. The critical longest partition still has two heads. Potential gains therefore concern overhead/cache/scheduling rather than a guaranteed reduction in critical-path arithmetic. Projection and vocabulary row domains retain12 workers. Prefill still uses6; its single-token tail remains6 because the policy is min(8,pool size). B2 stays on the original full pool.

`run_active` publishes an active count with the existing generation release. Workers with index>=active acknowledge completion without invoking the callback. The coordinator still waits for all physical workers, so job-pointer lifetime, error handling and scratch reuse retain the original completion barrier. Inactive workers still perform bounded50us spin/park behavior. Consequently this tests useful-work partitioning within the same pool; it does NOT reproduce a process with only8 threads and cannot claim reduced thread count or guaranteed energy savings. A second pool would introduce extra threads and overlapping spin and is intentionally not part of this experiment.

Each head still runs the unchanged ascending key/channel arithmetic and private worker scratch. No model math, KV layout, memory sizes, prefill query pairing, context threshold, or API/sampling behavior changes. All nonattention calls route through run_active with the original full count.
