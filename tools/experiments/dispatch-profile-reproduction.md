This experiment profiles synchronous CPU-only SystemVerilog dispatch wall time. It does not change neural arithmetic, use GPU/PyTorch, or move calculations into C++. Existing `tools/profile_simulator.py` samples stacks and sweeps workers; this complementary profiler measures boundaries around already-existing dispatch calls.

Build the selected B8 profile with `--profile-dispatch` added to the normal isolated variant-builder flags. The flag defines `PROFILE_DISPATCH` for the C++ harness and gives the artifact a distinct directory. Without that compile flag, timing scopes and the diagnostic command disappear. In the experimental binary, `profile on`, `profile off`, `profile reset`, and `profile read` enable, disable, clear and return counters. Counters default off and use the main thread only.

`tools/profile_dispatch.py --binary PATH --output build/dispatch-profile.json` warms the simulator, then runs three alternating enabled/disabled pairs at 85- and 452-token prompts with 32 subsequent decode steps. It resets counters after prefill and the first prediction. Both modes must yield identical greedy IDs and bit-identical final full-vocabulary logits. The historical-dump barrier runs outside the measured decode interval. Call counts must match 28 layers per hidden family/attention and one vocabulary projection per decoded token.

The projection and attention scopes surround `pool.run` or `pool.run_group`: they include scheduling, worker input/output transport, worker SV evaluation and waiting. They exclude the main generated DPI wrappers and array copies. The enclosing eval scope includes both clock edges and their generated model evaluation. Subtracting dispatch scopes gives main SV normalization/activation/RoPE/argmax work, generated wrapper copies, classification and other coordinator work; it is **not pure scheduler overhead**. Host wall time outside eval includes IPC, command parsing/printing and Python transport. These are elapsed wall intervals, not summed worker CPU time. Hidden Q/K/V/O/gate/up/down and the vocabulary head are separate counters; grouped QKV and gate/up counters remain zero in single-token decode.

Enabled/disabled wall ratios estimate dynamic instrumentation effects in the same executable. They do not rule out code-generation differences introduced by compiling instrumentation, and scheduling/host drift can make enabled runs appear faster. Results identify where to investigate; they are not an optimization speed claim. The source manifest verifies the neural SV files and pool/descriptor code match the frozen B8 candidate.

The complete report is `reports/dispatch-profile-b8.json`. All 12 measured requests retained identical IDs and final full-vocabulary logit bits. Short-context eval averaged 23.00 ms/token: hidden projections 69.7%, vocabulary head 10.6%, attention 14.3%, and residual main-SV/wrapper/coordinator work 5.4% (1.25 ms). Host time outside eval averaged 0.057 ms/token. Long-context attention was 34.6–35.6% in individual enabled runs; across all runs hidden projections were approximately 53.0%, head 7.8%, attention 35.1%, residual 4.1% (1.38 ms). Host outside eval averaged 0.068 ms/token.

The enabled/disabled wall ratios were 0.961/0.940/0.971 short and 1.027/1.026/1.370 long. The last long run drifted substantially (40.69 ms/token versus 29.93–30.10 in the first two), while attention share stayed similar. Consequently, this experiment does not establish a precise instrumentation cost or a production throughput rate. It supports prioritizing projection arithmetic for short decode and attention/KV inner loops for longer context. Optimizing only Python transport or the coordinator cannot remove most of the measured work; even the residual category includes useful SV arithmetic.

Reproduction is intentionally archived rather than integrated into the production builder. Create a separate worktree at exact base `da66912`, then apply `tools/experiments/dispatch-profile.patch` from this archive. It contains the diagnostic header, C++ scopes/commands, optional isolated builder flag and Python driver; no SV source is changed. Build with:

```sh
python tools/build_projection_variant.py --lto --unchecked --masked-activation --unsigned-indices --fast-attention --parallel-attention --batched-prefill --block-unroll --compact-projection --group-projections --prefill-b8 --profile-dispatch
```

Then run the driver command above against the printed binary path during an exclusive CPU window. The full manifest, source hashes, checkpoint/tokenizer hashes, counters, raw token IDs and all overhead pairs are in the report. The neural SV files and worker pool/descriptor sources match the frozen B8 candidate exactly. This archive does not enable diagnostic commands in production.
