# Experimental FP32 KV model

This opt-in profile adds one coordinator-owned SV KV store to the combined attention model. It keeps FP32 scalar/verification projections, FP64 prefill projections and FP64 attention arithmetic, but narrows each normalized/rotated K and projected V into internal `shortreal` storage. It is not numerically identical to FP64 KV and is not enabled in the UI or defaults.

Build the combined hybrid flags with `--fp32-kv` instead of `--static-kv`. The builder requires B1/B4 projection support and batched parallel attention, and rejects FP32-prefill and static-KV combinations. The separately compiled storage archive uses the reviewed shortreal compiler and strict FP flags; stock main/worker flags are unchanged. Runtime capability profile is `fp32_b1_fp64_prefill_fp32_kv`, with separate `attention_arithmetic: fp64` and `kv_storage: fp32` fields. Canonical prefix policy is `none`; no cross-profile KV reuse is supported.

For each layer/token, the coordinator passes a validated 1024-element real K/V vector through an open-array DPI transport callback. The callback copies real ports and clocks the single storage module; narrowing occurs in SV. No worker owns or evaluates a storage module. Every pool dispatch completes synchronously before further coordinator writes; existing mutex/atomic publication makes completed writes visible to readers. Workers read the generated float arrays with exact float-to-double widening only. Existing causal limits remain unchanged, including batched queries after all block writes. Reset/truncation logically hides stale values rather than clearing storage.

Compile-time assertions require generated float elements and exactly 939524096 bytes (896 MiB) for the two arrays. Generated main-model headers contain neither old KV array. This is payload accounting, not an RSS measurement. Read ports keep arrays reachable without unsupported FLOAT public annotations. The generated DPI header is included by the harness so mismatched fixed/open-array ABI declarations fail compilation.

First build's smoke exposed a fixed-array/open-array callback mismatch before any numerical result; the declaration was corrected to open arrays. Final frozen artifact `c7a41fd46cb72ae0d2b1789c5be4b2926b8b7bb41ca440b0ecbe52fe6b3f5624` passes precision query, eight-token prefill and scalar prediction smoke. Full corpus, conversation, replay/suffix, capacity and performance evaluation remain independent gates. No quality-maintenance or speed claim follows from this smoke.
