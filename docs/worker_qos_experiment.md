# Optional worker QoS experiment

The archived opt-in experiment adds `--worker-qos-experiment` to build a single binary whose model arithmetic is identical across runtime selections. The trusted launch environment may specify `QWEN_EXPERIMENTAL_WORKER_QOS=DEFAULT` or `USER_INITIATED`. An unset/empty value observes existing scheduling without setting it. Invalid selectors fail before worker creation. Production builds without the opt-in flag do not inspect this variable and retain their existing behavior. There is no HTTP or mutable protocol scheduler setter.

On Apple platforms, each worker configures its own QoS once at startup and verifies requested class/relative-priority readback. Failure flows through the existing pool exception/join path. The coordinator does not call a setter. The read-only `worker_qos` command returns the selector, coordinator observations and immutable worker startup observations. These are requested classes, not effective temporary overrides or CPU/core placement. Explicit selection on non-Apple platforms fails clearly; unchanged selection remains portable.

The installed SDK documents that pthreads created without QoS attributes default to DEFAULT. A separate observation-only `std::thread` probe under this launcher saw coordinator USER_INTERACTIVE(33), all eight workers DEFAULT(21). That is not a measurement of the live simulator. [Apple's QoS API declarations](https://github.com/apple-oss-distributions/libpthread/blob/main/include/pthread/qos.h) explain that temporary overrides are not reflected by requested-class queries. [Apple's scheduling guidance](https://developer.apple.com/documentation/apple-silicon/tuning-your-code-s-performance-for-apple-silicon.md) recommends QoS APIs and measurement on actual hardware; it does not guarantee placement on a particular core class.

The measured comparison is DEFAULT versus USER_INITIATED at eight workers, using the same frozen executable and existing paired-head attention path. Require exact outputs, verified readback, unchanged coordinator class, warm pools and alternating request order before any speed claim. Worker-count4/6/8/12 comparisons have a separate kernel-route confound:4/8 use paired-head attention,6/12 use scalar fallback. Three helper tests and real unset/DEFAULT/USER_INITIATED readback passed. All three modes matched frozen f17 full-logit bits and IDs at85/452-context plus4-output continuations. ## Paired result

The [same-binary report](../reports/worker-qos-paired.json) records three alternating DEFAULT/USER_INITIATED pairs per85/452-token prompt with32 greedy outputs and eight workers. Every requested-class check around each request passed; coordinator stayed unchanged. All output IDs, positions and full-vocabulary bits matched. Worker telemetry is cached startup requested QoS, not effective in-flight priority.

Short total speedup ratios were0.938/1.131/1.022 (median1.022×), while decode ratios were1.030/1.192/1.031 (median1.031×). Long total ratios were1.002/0.985/1.003 (median1.002×); long prefill median0.998× and decode median1.022× (range1.003–1.035). All six decode ratios were positive, but total latency is mixed and approximately neutral long-context. This does not justify changing defaults. Keep the scheduler experiment optional; no core-placement or broad performance claim follows.

## Reproduction archive

Active runtime and build defaults do not include this scheduler experiment. `tools/experiments/worker-qos.patch` captures runtime, builder and helper-test changes from source base `0d21bcc` through `8f314bb`; SHA256 `e7c21d43988d8ba0cd049f4a55a46444b4271a5ab1c719b6ed370d185c71b91f`. It reverse-applies cleanly to the preserved original source worktree. Create an isolated checkout at the base, apply the patch, and use the manifest command in the raw reports with new output paths and `--worker-qos-experiment`. The archived `tools/check_worker_qos_real.py` and `tools/compare_worker_qos.py` operate only on explicitly supplied artifacts. Use the new binary’s verified hash for `--expected-sha`, run correctness first, and reserve an exclusive timing window.
